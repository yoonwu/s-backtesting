# KEYWORD LAB

네이버 검색광고 API로 키워드 **월 검색량 · 경쟁도 · 광고 경쟁 깊이**를 전수로 긁어와서,
"수요는 있는데 경쟁이 약한" 틈을 순위표로 뽑는 도구.

레버리지랩·볼스위칭 전수조사와 구조가 같다. 파라미터가 키워드일 뿐이다.

```
keyword-lab/
  naver-api.js   API 클라이언트 (서명 계산 포함)
  scan.js        씨앗 키워드 -> BFS 확장 -> data.js 생성
  index.html     결과 대시보드 (정렬·필터·CSV)
  seeds.txt      씨앗 키워드 목록
  test/          가짜 서버로 도는 테스트 (실제 키 불필요)
```

## 1. API 키 발급

1. https://searchad.naver.com 로그인
2. `도구 → API 사용관리 → 네이버 검색광고 API 서비스 신청`
3. 세 가지가 나온다:
   - **내 계정 ID** (숫자) → `customerId`
   - **액세스라이선스** → `apiKey`
   - **비밀키** → `secretKey`

무료다. 광고를 집행하지 않아도 발급된다.

## 2. 설정

```bash
cd keyword-lab
cp config.example.json config.json
# config.json 열어서 키 3개 채우기
```

`config.json` 은 `.gitignore` 에 들어 있어 깃에 올라가지 않는다.

## 3. 실행

```bash
node scan.js --seed "에코백,파우치,크로스백" --depth 2
# 또는
node scan.js --seed-file seeds.txt --depth 3 --max 3000
```

| 옵션 | 기본 | 설명 |
|---|---|---|
| `--seed` | — | 씨앗 키워드, 쉼표 구분 |
| `--seed-file` | — | 한 줄에 하나씩 적힌 파일 |
| `--depth` | 2 | 연관 키워드를 몇 단계까지 확장할지 |
| `--max` | 2000 | 최대 수집 개수 |
| `--delay` | 350 | 호출 간격(ms). 429 나면 늘린다 |
| `--fresh` | — | 캐시 무시하고 처음부터 |

끝나면 `data.js` 가 생긴다. **`index.html` 을 브라우저로 열면 표가 나온다.**
(`file://` 로 열어도 되게 JSON이 아니라 JS 파일로 떨군다 — `fetch` 는 CORS에 막힌다)

중간에 끊겨도 `cache.json` 에 남아서, 다시 돌리면 이어서 간다.

## 4. 화면 보는 법

| 컬럼 | 의미 |
|---|---|
| 월 검색량 | PC + 모바일 합계 |
| 모바일 비중 | 높을수록 모바일 상세페이지가 중요 |
| 경쟁도 | 네이버가 주는 값 (낮음/중간/높음) |
| 광고 경쟁 | `plAvgDepth`. 광고 노출 경쟁 깊이 0~15 |
| **기회 점수** | `검색량 ÷ (경쟁가중치 × (1 + 광고경쟁/15))` |

기회 점수는 **절대값에 의미가 없다.** 정렬용 상대 지표다.
검색량이 압도적이면 경쟁이 세도 위로 올라오고, 검색량이 같으면 경쟁 약한 쪽이 위로 온다.
공식이 마음에 안 들면 `naver-api.js` 의 `normalize()` 에서 바꾸면 된다.

**쓰는 법:** `키워드 포함`에 `제작`, `단체`, `주문` 같은 걸 넣고 `경쟁도: 낮음만` 으로 좁힌다.
거기 남는 게 실제로 노려볼 만한 자리다.

## 5. 안 될 때 — 여기서 대부분 막힌다

### 401 Unauthorized

**서명(X-Signature) 계산 문제다.** 규칙이 까다롭다.

```
서명 대상 문자열 = `{타임스탬프}.{METHOD}.{경로}`
                   예: 1753600000000.GET./keywordstool
```

- 경로는 **쿼리스트링을 빼야 한다.** `/keywordstool?hintKeywords=...` 가 아니라 `/keywordstool`
- METHOD는 **대문자** `GET`
- 타임스탬프는 **밀리초** (초 아님)
- HMAC-SHA256 후 **base64** (hex 아님)
- 요청 헤더의 `X-Timestamp` 와 서명에 쓴 타임스탬프가 **같아야 한다**

`naver-api.js` 의 `sign()` 이 이걸 처리한다. 테스트에서 서버가 독립적으로 재계산해 대조하므로,
테스트가 통과하면 서명 로직은 맞다.

### 403 Forbidden

`X-Customer` 에 **네이버 아이디를 넣은 경우**다. 여기 들어가는 건 검색광고의 **"내 계정 ID"(숫자)** 다.
광고시스템 우측 상단이나 API 사용관리 화면에서 확인한다.

### 결과가 비어서 옴 (200인데 keywordList 가 빈 배열)

키워드에 **공백이 들어간 경우**다. `"에코백 제작"` → `"에코백제작"` 으로 붙여야 한다.
`naver-api.js` 가 자동으로 제거하지만, 직접 호출할 때는 주의.

### 429 Too Many Requests

호출 제한. `--delay` 를 800~1500 으로 올린다.

### 그 외

- `hintKeywords` 는 **한 번에 최대 5개**
- 검색량이 `"< 10"` 같은 문자열로 오는 경우가 있다 (10 미만이라는 뜻)

